Chapter 1 · The question

Is the AI improvising, or following a script?

When an AI answers someone who is struggling, we usually ask one thing: was this reply good? We grade it, then grade the next one.

We ask something else. Line up many replies to many different people. Does the AI make the same moves, in the same order, whoever it is talking to?

?Why ask thisA reply can look excellent on its own and still be a fill-in-the-blanks template. You only see the template when you compare replies side by side.

Chapter 3 · Annotation

Experts mark what each sentence does

Trained clinicians read every reply and highlighted the text behind each behaviour, using a manual of 20 codes. We colour them in four families.

Your turn: click a tag in the reply. Watch where it lands on the line below.

Each tag becomes one tiny record: which move, and where it starts.
?Why keep so littleWe drop the words on purpose. Keeping only “what” and “where” means the method works on any labelled text, for any task, and never needs the reply itself.

Chapter 4 · Seats

Give every reply the same ten seats

Replies have different lengths. So we stretch each one onto the same ruler and cut it into 10 equal seats. Seat 1 is the opening. Seat 10 is the closing.

Sometimes a clinician gave one sentence two or more codes, so the tags start at the same spot. We keep them together as one slot (the outlined stacks), because nobody can tell which came first.

?Why seatsSeats let us count. Across thousands of replies we can now ask: what usually sits in seat 1? What sits in seat 10?
Chapter 5 · Transitions

Read the moves in order

Now read the slots from left to right, like a sentence. Each arrow is a transition: one move, then the next.

Tags inside the same slot get no arrow between them. We cannot see their order, so we do not invent one.

?Why order matters tooWhere a move sits and what it follows are two different habits. A move can keep a fixed seat (choreography), or keep following the same move (momentum). We measure both, and never count the same pattern twice.

Chapter 6 · Pooling

One reply proves nothing. Pool them all.

Then we play a guessing game. Hide a tag. If you only know its seat, how much easier is it to guess the move?

  • Choreography (C): how much easier guessing gets when you know the seat.
  • Momentum (M): how much easier it gets when you also know the move just before, beyond what the seat already told you.
?Why poolA script is a habit of the system, not of one reply. One tidy reply could be chance. Thousands of tidy replies are a habit.

Chapter 7 · The fair test

Shuffle, and compare with luck

Part of that number is luck. A model that gives a lot of advice will have advice in every seat. And small tables always show a few fake patterns.

So we run a fair test. Inside each reply we keep the same tags and the same positions, and only shuffle which tag sits where. The mix of moves stays identical. Only the arrangement is destroyed.

We do this 200 times. SCRIPT = real structure − average shuffled structure.

?Why shuffleIt gives the score a true zero. A system with no script scores 0, no matter how often it uses each move. That is what lets us compare models fairly.

Chapter 8 · Result 1

All five models follow a script

1

Every model scores far above zero: 0.083 to 0.118. The same tags with random labels score about zero (−0.004).

2

They share one blueprint: empathy opens and advice fills the middle. In four of the five, questions close.

3

The seats (C) are almost the same for all five. The chaining (M) differs. Claude chains the most.

4

When one AI annotator labels everyone the same way, the human therapist has the weakest seat pattern: C = 0.045, against 0.063–0.086 for the models.

?Why a second annotatorThe clinicians only labelled the AI replies. Re-labelling every reply, the therapist's included, with one blind annotator puts humans and models on the same ruler, and shows the pattern is not one coder's habit.

Chapter 9 · Result 2

Does the script listen to the person?

A script is only a problem if it ignores the person. So we ask what actually changes the behaviour: the seat, the person's state, or the stage of the conversation.

1

For the models, the seat explains 6–8.5% of the behaviour. The person's state explains only 0.5–1.1%.

2

The therapist listens first and advises later: advice rises from 8% of moves in turns 1–3 to 28% in turns 8–10. The models begin advice-heavy, at 27–52%, and change less.

3

When a message is emotionally intense, the therapist cuts advice from 29% to 13%. No model cuts it by more than 5 points. An explicit safety cue moves the models much more: 65–88% of the therapist's shift, against 22–36% for emotional intensity.

4

The script restarts every turn. How one reply ends does not shape how the next one begins.

?Why test thisHigh structure alone does not prove an AI ignores people. Measuring the person's share separately tells us whether the structure answers the person or comes before them.

Chapter 10 · Result 3

Standard evaluation cannot see it

We took pairs of replies from the same system with exactly the same moves, arranged differently. An expert-protocol AI judge rated them on a 1–5 scale.

The more scripted reply scored +0.004, which is no difference. The longer reply in the same pairs scored +0.039, so the judge can notice small things. It just does not notice arrangement.

A published training method (MINT) that makes tactics vary across turns lowered stickiness (0.571 → 0.422) and choreography (C 0.150 → 0.112), but C stayed above the human level (0.014), close to a simple tactic-list prompt (0.110). Under a second, position-blind labelling, C rose instead (0.093 → 0.195).

?The takeawaySCRIPT measures how a system arranges its behaviour, not whether one reply is good. Report it next to quality, not instead of it.

The whole method in one breath

1

Tag each behaviour and keep only what it is and where it starts.

2

Seat every tag in one of 10 seats, and read slots in order.

3

Pool all replies and measure how well seat (C) and previous move (M) predict the behaviour.

4

Shuffle inside each reply and subtract what luck gives. What is left is SCRIPT.
