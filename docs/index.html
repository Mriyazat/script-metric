Contribution 1: what we found

We found that the replies are not simply better or worse. They follow a repeated routine. Across hundreds of replies the same therapeutic moves land in the same places: the model opens by validating the person, moves into advice and problem-solving through the middle, and closes with a question or a recommendation, even when the person's situation is completely different. The moves also chain in predictable ways, and they differ from how a human therapist responds. We called this scripted therapeutic responding. This matters clinically: the models can sound supportive while drifting from what the person actually raised, or even echo the person's own negative self-beliefs back to them, something human therapists do far less.

But a description is not a measurement

Contribution 1 could point at the pattern, but it could not put a number on it. How scripted is a given model? Is the pattern real, or a coincidence of the data? Does one model run a tighter script than another? A description read off the annotations cannot answer these, and it cannot be compared cleanly across models or datasets.

Contribution 2: measuring it

This is what we build in Contribution 2. It takes the same clinician annotations and turns the observation into a single, chance-calibrated number: how much of a model's behaviour was fixed by where a move sits in the reply and what came just before it, rather than by what the person actually said.

Most evaluation asks how good a response is. SCRIPT, our metric, asks something else: how much of a reply's behaviour was settled before the user even spoke. The deeper finding is that LLM conversations have a measurable behavioural syntax, and the metric below is the instrument that reads it, separating where behaviours sit (choreography) from how they follow one another (momentum), always in excess of chance.

“i feel like i'm not good enough, mainly because i haven't landed an ideal job since graduating, and i don't have a boyfriend either. people always talk about the importance of having a career and a family, and it makes me feel like i haven't accomplished much. compared to my friends, my life seems to be at a standstill.”

We are going to turn this one reply into numbers and end with Claude's profile: a fingerprint of how it arranges behaviour.

To do that, each highlight becomes an event: a behaviour label together with where it sits in the reply. We then measure how predictable those behaviours are, counted in bits. The next three steps build exactly this, in order: what a position is (Step 1), how the events are formed (Step 2), and how we measure their uncertainty in bits (Step 3).

A bin is a slice of position in the reply. We split the reply into 5 equal parts by length, and a behaviour's bin is simply which part it starts in.

From here on, the words are gone. The metric only ever sees this list of (behaviour, bin) pairs.

A note on that “start char” column: it is just the position where a highlight begins, counting characters from the start of the reply, so character 0 is the very first letter. The highlight itself is a whole phrase, not one character; we only record where it starts, not how long it is. When several highlights share the same start, like the ones at char 220 or 308, it is because the clinician marked more than one behaviour on the same passage.

Step 3The behaviour mix — and what a “bit” is

What is a bit? A bit is a unit of uncertainty — how hard something is to guess. Imagine I pick one event at random and you must guess its behaviour with yes/no questions. If there were two equally likely behaviours, one question settles it: that is 1 bit. Four equally likely behaviours need two questions: 2 bits. If some behaviours are more common than others, it is easier than the worst case, so it costs fewer bits. The exact measure is Shannon's entropy:

H(L) = − ∑ p · log2 p

H(L) = 1.789 bits — the difficulty of the guessing game with no hints. Everything that follows measures how much easier hints make it.

Step 4Hint #1: position  →  choreography C

First hint: I tell you the bin. Does that help you guess the behaviour? Build the position table — how many events of each behaviour fall in each bin:

Inside a single bin the guess is usually easier. Bin 0 holds 7 events (2 empathy, 4 advice, 1 other), so its uncertainty is only H = 0.29·1.81 + 0.57·0.81 + 0.14·2.81 = 1.379 bits, less than the 1.789 we started with. Averaging every bin's uncertainty (weighted by how many events it holds) gives:

H(L | position) = 1.554 bits

The drop from H(L) to H(L | position) is how many bits the position hint saved. That drop is called mutual information — literally “how much knowing one thing tells you about another”:

I(L; position) = 1.789 − 1.554 = 0.234 bits

To make it a share (0 = position tells you nothing, 1 = position tells you everything), divide by the starting uncertainty. That share is choreography:

C = I(L; position) / H(L) = 0.234 / 1.789 = 0.131

Step 5Hint #2: the previous move  →  momentum M

Second hint, on top of position: I also tell you the previous behaviour. Build the transition table — how often each behaviour follows each other one:

previous \ nextempathyadvicequestionother
empathy0311

We measure the previous move's help after position is already known — the “| position” below. That is the crucial trick: the previous move only gets credit for what position had not already explained, so the two hints never count the same bit twice.

H(L | position, previous) = 0.571 bits    I(L; previous | position) = 1.554 − 0.571 = 0.983 bits
M = I(L; previous | position) / H(L) = 0.983 / 1.789 = 0.550

Add the two hints together and you get the total structural share, rigidity:

R = C + M = 0.131 + 0.550 = 0.681

Every number here is real, pooled over 8,502 of Claude's annotated events. With no hint the behaviour mix is spread out (~1.95 bits). Knowing only where the behaviour sits, then what came just before, steadily sharpens the odds and drops the difficulty. That drop, in excess of chance, is choreography + momentum — the SCRIPT score.

Step 6Is it real? Chance, SCRIPT, and z

R = 0.681 looks big — but here is the catch. With only 28 events, a lot of “structure” appears by pure luck: advice is half the events, so guessing “advice” is easy even with no real pattern, and small tables throw up accidental regularities. We must subtract that luck.

The fix is a shuffle test. Keep every event's bin fixed, but randomly reshuffle which behaviour sits where — inside this reply. That destroys any real arrangement while keeping the same behaviour mix and the same table sizes. Whatever R the shuffle still produces is the chance level. Do it thousands of times and average:

chance R (average of shuffles) = 0.628
SCRIPT = Rreal − Rchance = 0.681 − 0.628 = 0.052

z tells us whether that leftover is real or luck. It counts how many “shuffle standard deviations” the real value sits above chance (sd = 0.063 here). Above about 2 means “unlikely to be luck.”

z = (0.681 − 0.628) / 0.063 = 0.84
The lesson of one reply. Almost all of that impressive R = 0.681 was chance (0.628). Only 0.052 is real, and z = 0.84 is well below 2 — it could easily be luck. One reply is simply too little. This is exactly why the metric pools all ~800 of a model's replies: with that much data the chance level shrinks, the real signal stands out, and z climbs to 38–56.

Step 7What we have: the profile

Notice we already built two tables: where each behaviour sits (position, Step 4) and what follows what (transition, Step 5). Those two tables are the profile — Claude's routine written down as numbers. From this single reply the profile is rough, but it is the exact object that, pooled over all replies, becomes a stable fingerprint.

Step 8From profile to naming the model

One reply cannot name a model — its profile is too noisy (that low z). But pool all of a model's replies and its profile settles into a stable fingerprint. To name an unknown set of replies, we ask, for each candidate model: how likely is this arrangement under that model's profile? — reading each event's position- and transition-probability off the profile and multiplying them:

score =  average of  log Pposition(behaviour, bin)  +  log Ptransition(behaviour | previous)

The model whose profile makes the replies most likely is the name we give. On single replies this is a coin-toss; on a handful it becomes reliable; across the full benchmark the profiles identify the generating model correctly. The score says how scripted; the profile says which script — and therefore which model.

A meaningful zero. A system driven by what the person actually said reads 0 in expectation — however skewed its behaviour mix, however small the sample. A system that decides its moves before reading the input reads high, however fluent each move is. That is what the within-response shuffle buys, and it is why these rows can sit on one axis at all.

SCRIPT — a reference-free metric of behavioural scriptedness, computed from span annotations alone: no reference outputs, no user ratings, no logits, no model access, no second system.

The metric is one file of numpy and pandas. Code, the full reproduction pipeline, and the data-download scripts are on GitHub.
